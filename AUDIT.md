# Аудит консольной версии DP_Repeated_Tasks

Объект: `DP_Repeated_Tasks.cpp` (509 строк, один файл, C++98-стиль).
Сборка: `g++ -std=c++98 -Wall -Wextra` — **проходит без единого предупреждения**.
Именно поэтому все найденные дефекты — логические и runtime, компилятор их не ловит.

Все выводы ниже **воспроизведены на собранном бинарнике** (g++ 13.3.0, Ubuntu 24.04,
valgrind, clang-tidy). Для каждого пункта указан способ повторить.

## Critical

### 1. Бесконечный цикл при EOF на stdin

`getInt()` (44–57), `showTaskList()` (420–424), `waitEnter()` (39–42).

```cpp
cin.clear();                 // снимает eofbit
cin.ignore(10000, '\n');     // снова мгновенно падает по EOF
```

При EOF `cin.clear()` снимает флаг, `ignore()` тут же выставляет его обратно, и цикл
крутится без остановки, печатая приглашение. Проверки `cin.eof()` нет нигде.

Срабатывает при: `Ctrl+D`, подаче ввода из файла/пайпа, закрытии терминала,
запуске из CI или скрипта.

```
$ timeout 5 ./app < /dev/null ; echo $?
124                      # убит по таймауту, сам не завершился
$ wc -c < out.txt
244318292                # 244 МБ «Введите число от 0 до 6:» за 5 секунд
```

**Исправление:** в `getInt()` и во всех местах чтения проверять `if (cin.eof())` и
завершаться корректно (с сохранением). Это же чинит и `waitEnter()`.

### 2. SIGSEGV в `formatDue()` при некорректной дате

`Task::formatDue()` (115–121):

```cpp
tm* ti = localtime(&dueDate);          // может вернуть NULL
strftime(buf, sizeof(buf), "...", ti); // разыменование без проверки
```

`localtime()` возвращает NULL, если `time_t` не представим в `struct tm`.
Значение `dueDate` приходит из файла **без какой-либо валидации** (строка 169).

```
$ valgrind ./app_dbg
Invalid read of size 4
   at __strftime_internal (strftime_l.c:471)
   by Task::formatDue() const (DP_Repeated_Tasks.cpp:119)
   by Task::printTree(...)  (DP_Repeated_Tasks.cpp:135)
   by showTaskList()        (DP_Repeated_Tasks.cpp:410)
 Address 0x8 is not stack'd, malloc'd or (recently) free'd
Process terminating with default action of signal 11 (SIGSEGV)
```

Повтор: положить в `dueDate` значение `9223372036854775807`, открыть список задач.
Падает **на отрисовке списка** — то есть база становится полностью недоступной.

**Исправление:** `if (!ti) return "(некорр. дата)";` плюс валидация диапазона при загрузке.
Заодно `strftime` возвращает 0 при нехватке буфера — возврат игнорируется (clang-tidy `cert-err33-c`).

### 3. Сохранение неатомарно и не проверяется

`saveData()` (444–458):

```cpp
ofstream out(FILENAME);      // <- файл УЖЕ обрезан в ноль
if (!out) { ... return; }    // проверка только на открытии
out << ...;                  // ошибки записи не проверяются
out.close();                 // результат close() не проверяется
cout << "Сохранено в " << FILENAME << "\n";   // рапорт об успехе — всегда
```

Состояние потока проверяется только при открытии. Любая ошибка записи
(нет места, квота, I/O) молча проглатывается, а пользователю сообщается «Сохранено».
Резервной копии не создаётся, старый файл уничтожен ещё в момент открытия.

```
before: 2928 байт, 20 задач
$ ( ulimit -f 1; ./app )     # обрыв записи на середине
after : 1024 байт,  7 задач
=== потеряно 13 из 20 задач, бэкапа нет ===
```

То же произойдёт при `Ctrl+C`, убийстве процесса или отключении питания во время записи.
Дальше вступает п. 5: обрезанный файл загрузится молча и потеря будет закреплена.

**Исправление:** запись во временный файл → `flush` → `fsync` → проверка `out.good()` →
атомарный `rename()`. Плюс ротация одной резервной копии (`.bak`).

### 4. Удаляется не та задача при коллизии ID

`removeById()` (206–215) удаляет **первое** совпадение по ID. Уникальность ID нигде
не обеспечивается: `loadData()` (467) берёт `nextId` из файла как есть и никогда
не сверяет его с фактическими ID задач.

Сценарий воспроизведён: в базе две задачи с `id == 1`. Пользователь открывает
задачу №2 («ВТОРАЯ»), выбирает «4. Удалить», подтверждает, видит «Удалено.»

```
Пользователь удалил задачу №2 = 'ВТОРАЯ'. Осталось в файле:
ВТОРАЯ-её удаляем        <- уцелела
                         <- 'ПЕРВАЯ' уничтожена вместо неё
```

Уничтожается **другая** задача, вместе со всем её поддеревом, без каких-либо признаков ошибки.

Коллизия ID достижима через: обрезанный/повреждённый файл (п. 3 и 5), пустой файл
(`toInt("") == 0` → `nextId = 0`), ручную правку, восстановление старого бэкапа,
слияние двух файлов, две одновременно запущенные копии программы.

**Исправление:** после загрузки пересчитывать `nextId = max(всех id) + 1` и проверять
уникальность; при дубликатах — перенумеровывать. Долгосрочно — заменить поиск по ID
на прямую адресацию узла (путь в дереве).

### 5. Загрузчик полностью доверяет содержимому файла

`Task::load()` (162–181) и `loadData()` (460–476): ни одной проверки состояния потока,
ни одной границы на счётчики, ни одной валидации значений. `toInt()` при неудаче
молча возвращает 0.

**5a. Счётчик подзадач не ограничен** — `subtaskCount = 2000000000` на обрезанном файле:
```
terminate called after throwing an instance of 'std::bad_alloc'
Aborted (exit 134)
```
Исключение не перехвачено нигде — `terminate()`, аварийное завершение.

**5b. Рекурсия не ограничена** — вложенность 50 000 уровней:
```
Segmentation fault (exit 139)    # переполнение стека в load()
```
`save()`, `printTree()`, `collectAll()`, `removeById()` рекурсивны так же.

**5c. Пустой файл = тихое стирание базы.** `getline` не удаётся, `toInt("")` даёт 0 →
`nextId = 0`, `cnt = 0`, `rootTasks.clear()`. Все задачи исчезают, ошибка не выводится.
Ровно этот файл остаётся после прерванного сохранения (п. 3).

**Исправление:** проверять `in.good()` после каждого `getline`, проверять маркеры
`BEGIN`/`END`, ограничить счётчики и глубину, валидировать enum'ы и временные метки,
при ошибке — **не затирать** текущие данные, а сообщить и оставить файл нетронутым.

### 7. Канбан-доска ломает UTF-8 и вёрстку

`showKanbanDifficulty()` / `showKanbanUrgency()` (242–245, 275–278):

```cpp
if (sh.length() > 22) sh = sh.substr(0, 22);   // БАЙТЫ, не символы
cout << left << setw(22) << sh                 // выравнивание по БАЙТАМ
```

`std::string::length()`, `substr()` и `setw()` работают с байтами, а кириллица в UTF-8
занимает 2 байта на символ. Результат:

```
| Подготовить | Полить цвет? | Sync backup drive  |
   bytes=74  chars=51        <- граница таблицы 72 символа
```

1. **Порождается невалидный UTF-8** — `substr(0,22)` разрезает кириллический символ
   пополам. `iconv -f UTF-8 -t UTF-8` отвергает строку; в дампе видна висячая
   ведущая байт-последовательность `321` без продолжения.
2. **Колонки не сходятся** — строка данных 51 символ против рамки в 72.
3. **Обрезка по 22 байтам = 11 русских букв**, поэтому суффикс `[Xд Yч]` —
   собственно показатель давности, ради которого доска и существует — у русских
   названий **не виден никогда**.
4. **Верхняя рамка 70 символов**, остальная таблица — 72 (строки 220 против 222).

**Исправление:** функции `utf8_width()` и `utf8_truncate()` (учесть, что ANSI-ширина
кириллицы = 1, но байт = 2), padding считать по ширине, а не через `setw`.
Дополнительно `SetConsoleOutputCP(CP_UTF8)` для Windows-консоли.

### 8. `formatAgo()` даёт математически несогласованное разложение

`Task::formatAgo()` (99–112):

```cpp
int days   = hours / 24;
int months = days / 30;      // база 30
int years  = days / 365;     // база 365
...
toStr(years) + "г " + toStr(months % 12) + "м " + toStr(days % 30) + "д"
```

`years`, `months` и остаток считаются **независимо от одной и той же величины**,
причём в несовместимых базах: 12 × 30 = 360 ≠ 365. Остаток `days % 30` — это остаток
от деления на 30, а не «дни сверх лет и месяцев». Ошибка накапливается на 5 дней в год:

| Реальный интервал | Показывает | Должно быть |
|---|---|---|
| ровно 365 дней | `1г 0м 5д 0ч` | `1г 0м 0д` |
| ровно 730 дней | `2г 0м 10д 0ч` | `2г 0м 0д` |
| ровно 400 дней | `1г 1м 10д 0ч` | `1г 1м 5д` |

**Исправление:** последовательное вычитание (`years = days/365; days -= years*365;
months = days/30; days -= months*30;`), а лучше — календарная разница через `localtime`,
чтобы учитывать реальную длину месяцев и високосные годы.

Положительно: `if (diff < 0) diff = 0` (98) корректно защищает от «будущего»
`lastDone`, но делает это молча — сдвиг часов или смена часового пояса маскируются под «<1ч».

### 9. Файл данных ищется относительно текущего каталога

`FILENAME = "repeated_tasks.dat"` (187) — относительный путь, резолвится от CWD.

```
данные лежат в: /.../audit/repeated_tasks.dat (1 задача)
$ cd elsewhere && ../app
Корневых задач: 0
-> здесь молча создана новая пустая база: yes
```

Запуск из другого каталога (из ярлыка, из IDE, двойным кликом, из другой папки в
терминале) показывает пустой список и создаёт **вторую** базу. С точки зрения
пользователя — «все задачи пропали». Дальнейшая работа пишет уже в новый файл.

**Исправление:** резолвить путь относительно `%APPDATA%` / `$XDG_DATA_HOME`
(fallback — каталог исполняемого файла), плюс необязательный аргумент командной строки.

### 10. Новая задача считается только что выполненной

`Task()` (92): `lastDone(time(0))`. Только что созданная задача, которую никогда
не выполняли, показывает `[<1ч]` — «выполнена только что».

Основная метрика приложения («сколько прошло с последнего выполнения») стартует
с заведомо ложного значения, и задача не попадёт в поле зрения ровно столько,
сколько длится её обычный цикл.

**Исправление:** отдельный флаг `neverDone` (или `lastDone = 0` как sentinel)
и вывод «никогда» вместо интервала.

## Low / качество кода

- **Мёртвый код:** `findById()` (197) не вызывается ниоткуда, кроме самой себя.
- **Заголовки:** используется `std::pair`/`make_pair` без `#include <utility>` (работает
  только на транзитивном включении); `<algorithm>` включён, но не используется.
- **Дублирование:** `showKanbanDifficulty()` и `showKanbanUrgency()` (218–282) —
  ~60 строк, различающихся одним полем. Любая правка вёрстки требуется дважды.
- **Опасная адресация:** `Task*` указывают внутрь `vector<Task>`; любой `push_back`
  в родительский вектор их инвалидирует. Сейчас код спасает только то, что `flat`
  перестраивается на каждой итерации `showTaskList()` — то есть корректность держится
  на случайности, а не на инварианте.
- **Глобальное изменяемое состояние:** `rootTasks`, `nextId` (185–186).
- `using namespace std;` в глобальной области; публичные поля без инкапсуляции.
- `clearScreen()` (35) — 40 переводов строки; на высоком терминале не очищает, историю
  прокрутки затирает. Уместнее ANSI `\033[2J\033[H`.
- C++98-идиомы: `0` вместо `nullptr`, `stringstream` вместо `to_string`, индексные циклы.
- **Нет инфраструктуры:** ни `CMakeLists.txt`/`Makefile`, ни `.gitignore`
  (в репозиторий попадёт `repeated_tasks.dat`), ни тестов, ни CI. README — одна строка.
- **Windows:** исходник в UTF-8 без BOM, вывод без `SetConsoleOutputCP(CP_UTF8)` —
  в `cmd.exe` вся кириллица превратится в мусор.

## Точки роста

### Главное: в приложении «Repeated Tasks» нет повторения

Поиск по `interval|period|repeat|повтор|период` — ни одного поля в модели. Сейчас есть
только «когда последний раз делали» и одноразовый срок. Отсюда:

- **Нет периода повторения.** Нельзя сказать «поливать цветы раз в 3 дня». А это —
  заявленное назначение программы.
- **Отметка «выполнено» (384) не двигает срок.** `dueDate` остаётся в прошлом навсегда,
  и после первого выполнения поле теряет смысл.
- **Нет понятия «просрочено».** `formatDue()` печатает дату, но ничто не подсказывает,
  что она уже прошла. Пользователь должен сравнивать даты глазами.

Это ядро продукта; всё остальное — надстройки. Минимальная модель: поле
`repeatInterval` (+ единица измерения), при отметке о выполнении `dueDate += interval`,
и подсветка просроченных в дереве и на досках.

### Функциональность

- **Сортировка и фильтрация.** Список — строго в порядке добавления, колонки канбана
  тоже. Нет «сначала самые просроченные», нет фильтра «только высокая срочность».
- **Поиск.** Секция кода так и называется — `// ПОИСК / СБОР` (189), но поиска нет,
  а единственная функция в ней мертва (`findById`).
- **История выполнений.** Хранится только последняя отметка, поэтому нельзя ни увидеть
  регулярность, ни построить статистику, ни отменить ошибочную отметку.
- **Матрица приоритетов.** Сложность и срочность уже есть — просится матрица
  Эйзенхауэра (срочность × важность) и интегральный приоритет вместо двух отдельных досок.
- **Интерактивный канбан.** Доска только читает; переносить задачу между колонками
  с неё нельзя.
- **Массовые операции**, отмена последнего действия, экспорт в CSV/Markdown.

### Архитектура

1. Разнести на модули: `Task`/модель, хранилище (сериализация), UI-слой. Сейчас
   `printTree` и `save` — методы одной структуры, модель намертво сшита с `cout`.
2. Вынести формат хранения в устойчивый (JSON/SQLite) вместо позиционного построчного —
   это само снимает пп. 4, 5 и вопрос экранирования.
3. Убрать глобалы, заменить `Task*` на стабильные идентификаторы или индексные пути.
4. Тесты на `formatAgo()`, сериализацию и загрузку битых файлов — все 5 critical-дефектов
   ловятся юнит-тестами за минуты.
5. `CMakeLists.txt` + `.gitignore` + сборка с `-Wall -Wextra -fsanitize=address,undefined`
   в CI.

## Рекомендуемый порядок

1. **Сразу:** пп. 1, 2, 3, 5 — падения и потеря данных. Это ~50 строк правок.
2. **Затем:** пп. 4, 6, 9, 10 — тихая порча и потеря данных.
3. **Потом:** пп. 7, 8 — некорректный вывод; вынести общий код досок.
4. **Дальше:** период повторения + просрочка — то, ради чего приложение существует.
5. **Фоном:** тесты, сборка, разделение на модули.
